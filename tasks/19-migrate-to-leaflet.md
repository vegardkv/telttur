# Task 19: Migrate from Folium to Direct Leaflet HTML/JS/CSS

## Motivation

The current stack uses Folium to generate the interactive map HTML. While Folium was invaluable for rapid prototyping, it now creates friction:

- **Limited JS control**: Custom interactivity requires injecting raw JS via `_JsBlock` hacks and Jinja2 template overrides. This is fragile and hard to debug.
- **Bloated output**: Folium generates verbose HTML with long auto-generated variable names, repeated inline styles, and redundant boilerplate — necessitating a multi-pass optimization pipeline (`optimize.py`) just to get file sizes under control.
- **Performance**: The sheer number of DOM elements (one `<circle>` per lake marker) causes lag on pan/zoom at national scale. Direct Leaflet gives access to Canvas rendering, WebGL layers, or data-driven approaches that Folium cannot expose.
- **Maintainability**: Scoring logic is duplicated — once in Python (for initial rendering) and again in embedded JS (for interactive recalculation). A clean separation of data and presentation would reduce this.

Migrating to a hand-authored Leaflet frontend with a JSON data file gives full control over rendering, interactivity, and performance while keeping the serverless static-hosting model.

## Architecture

### New output structure

```
output/
├── index.html          # Main HTML page (hand-authored, checked into repo)
├── app.js              # Application JS (hand-authored, checked into repo)
├── style.css           # Styles (hand-authored, checked into repo)
├── data.json           # Generated by Python pipeline (gitignored)
└── data_<region>.json  # Alternative data files for different regions
```

### Data flow

```
[Python pipeline]                    [Static frontend]
                                     
 N50 FGDB files                      index.html
     ↓                                  ↓ loads
 Extract + Score                     app.js
     ↓                                  ↓ fetches
 data.json  ──── static hosting ───→ data.json
                                        ↓
                                     Leaflet renders
```

### data.json format

The Python pipeline produces a single JSON file containing all pre-computed data. The frontend reads this and renders everything client-side.

```jsonc
{
  "meta": {
    "generated": "2025-05-20T12:00:00Z",
    "bbox": [59.8, 10.4, 60.12, 10.9],
    "region": "Oslo"
  },
  "lakes": [
    // Compact array-of-arrays for minimal file size
    // [lat, lng, area_m2, cabin_score, access_score, ar5_score, fishing_score, composite_score, access_dist, cabin_density, industrial_dist, residential_dist, fish_species_count, ...extra]
    [60.012345, 10.543210, 52340, 4, 5, 3, 2, 2, 1234.5, 0.003, 5200, 3100, 3],
    // ...
  ],
  "lake_fields": ["lat", "lng", "area", "cabin", "access", "ar5", "fishing", "composite", "access_dist", "cabin_density", "ind_dist", "res_dist", "fish_count"],
  "roads": {
    // GeoJSON FeatureCollection (only if roads are shown)
    "type": "FeatureCollection",
    "features": [...]
  },
  "config": {
    // Scoring thresholds and interactive control defaults
    // so the frontend can do threshold-based recalculation
    "scoring": { ... },
    "interactive": { ... }
  }
}
```

Key design decisions:
- **Array-of-arrays** for lakes (not array-of-objects) — saves ~40% JSON size at 50k+ lakes
- **Field index mapping** via `lake_fields` — the frontend knows which index corresponds to which attribute
- **Pre-computed scores** — no scoring logic in JS; only threshold checks for interactive re-filtering
- **Roads as GeoJSON** — Leaflet natively consumes this; no conversion needed
- **Config block** — the frontend reads thresholds/defaults from the data file itself, so the HTML/JS never needs updating when config changes

### Frontend (index.html + app.js + style.css)

These files are **hand-authored source files** checked into the repo (not generated). They:

- Load Leaflet from CDN
- Fetch `data.json` (path configurable, default `./data.json`)
- Render lakes as CircleMarkers (or Canvas-based layer for performance)
- Render roads as GeoJSON polylines (if present)
- Build interactive control panel (sliders, checkboxes) from `config` block in data
- Handle popup rendering with colored score badges
- Re-filter/re-color markers on slider/checkbox changes using pre-computed values + simple threshold math

### Python pipeline changes

**`map_generator.py`** — Gutted and replaced:
- Remove all Folium code
- New `generate_data(lakes_gdf, roads_gdf, config) → dict` that builds the JSON structure
- New `save_data(data, output_path)` that writes `data.json`
- Optionally: `save_data_js(data, output_path)` that writes `const DATA = {...};` for single-file deployment

**`maputils/optimize.py`** — **Delete entirely**. No longer needed; the HTML/JS is hand-written and already minimal. Any future optimization (e.g., gzip, field pruning) is a separate concern.

**`maputils/interactivity.py`** — **Delete entirely**. Interactive controls move to `app.js`.

**`main.py`** — Update the `generate` command:
- Instead of calling `generate_map()` + `save_map()`, call `generate_data()` + `save_data()`
- Remove the `optimize` CLI command (or repurpose for JSON compression later)
- Print data.json file size instead of HTML size

**`config.py`** — Simplify:
- Remove `output.minify` (no longer applicable)
- Remove `output.coordinate_precision` (handle in `save_data()` with a simple round)
- Remove `map.base_map` (the frontend handles tile layer selection)
- Remove `map.use_marker_cluster` (frontend decides rendering strategy)
- Remove `map.include_osm_layer` (frontend HTML controls this)
- Keep `map.interactive_controls` config (serialized into `data.json` for the frontend)

**Scoring modules** — No changes. They continue to produce scored GeoDataFrames. The only change is in how the scores are serialized (JSON arrays instead of Folium popup HTML).

## Migration steps

### Phase 1: Data export (Python side)

1. Create `src/telttur/data_export.py`:
   - `build_lake_data(lakes_gdf, config) → list[list]` — converts GeoDataFrame rows to compact arrays
   - `build_road_data(roads_gdf) → dict` — converts to GeoJSON FeatureCollection
   - `build_config_block(config) → dict` — extracts thresholds and interactive defaults
   - `export_data(lakes_gdf, roads_gdf, config, output_path)` — assembles and writes `data.json`
2. Wire into `main.py` as the new output step (replace Folium generation)

### Phase 2: Frontend scaffold

3. Create `web/index.html` — minimal HTML with Leaflet CSS/JS from CDN, links to `app.js` and `style.css`
4. Create `web/style.css` — control panel styles, popup styles, score badge colors (extracted from current inline CSS in `interactivity.py`)
5. Create `web/app.js` — Leaflet map initialization, data fetch, marker rendering, popup builder

### Phase 3: Interactive controls

6. Port the interactive control panel from `interactivity.py` JS to `web/app.js`:
   - Slider controls for accessibility range, cabin density threshold, AR5 buffers
   - Checkbox toggles for scoring dimensions
   - Real-time marker re-coloring based on threshold checks against pre-computed values
7. Port score badge rendering (colored labels in popups)

### Phase 4: Cleanup

8. Delete `src/telttur/maputils/optimize.py`
9. Delete `src/telttur/maputils/interactivity.py`
10. Remove Folium-specific code from `map_generator.py` (or delete and replace with `data_export.py`)
11. Remove `folium` from `pyproject.toml` dependencies
12. Remove the `optimize` CLI command from `main.py`
13. Clean up `config.py`: remove `minify`, `coordinate_precision`, `base_map`, `use_marker_cluster`, `include_osm_layer`
14. Update all config YAML files to remove obsolete fields

### Phase 5: Verify

15. Generate `data.json` for local, regional, national configs
16. Open `web/index.html` in browser, verify rendering matches current Folium output
17. Test interactive controls (sliders, checkboxes, popups)
18. Compare `data.json` file size to current minified HTML — should be significantly smaller
19. Verify GitHub Pages deployment works (static files only)

## File placement

The `web/` directory holds the static frontend source files:

```
web/
├── index.html
├── app.js
└── style.css
```

The Python pipeline writes `data.json` into `output/` (as before, gitignored). For local development, the frontend fetches `../output/data.json` (or a dev server serves both). For deployment, both `web/*` and the generated `data.json` are published together.
